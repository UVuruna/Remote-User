### 5. Layer violations

- **`server/actions_api.py:90`** — `from gui.controls_editor import
  merge_shipped_pools` inside `_merge_shipped_pools_once()`. The function
  is actually DEFINED in `server/gui/controls_data.py:217`, a module whose
  own docstring states "no Qt in this module … nothing here imports a
  widget" specifically so headless code can use it.
  `controls_editor.py` merely re-imports the same name at its own line 67
  (`from gui.controls_data import (… merge_shipped_pools …)`), and Python
  lets a second module import it transitively from there. The practical
  effect: the **headless server path** (`server/main.py` → `web.py` →
  `actions_api.py`, no GUI) pulls in `gui.controls_editor`, which imports
  `PySide6.QtCore/QtGui/QtWidgets` at module level
  (`controls_editor.py:55-57`) — a headless deployment without PySide6
  installed would hit an `ImportError` here, currently swallowed by the
  broad `except Exception as e: logger.warning(...)` around it
  (`actions_api.py:96`), so the merge silently no-ops instead of crashing.
  One-line fix: import from `gui.controls_data` instead. See R1.
- No GUI-touching-files-directly or engine-importing-GUI pattern found
  elsewhere in `server/*.py` (the two `webbrowser.open()`/`subprocess.Popen`
  hits in `main_window.py`/`traffic_window.py` are legitimate OS-shell
  actions — opening a browser link, revealing a file in Explorer — not
  layer violations).
