Popup test

Open this page inside a layout member window, then press the buttons from the phone. Watch two things every time: does the new window land inside the streamed picture, and can the layout still be raised afterwards.

1
A separate browser window TOP-LEVEL — not owned A brand-new window of the same process. Nothing owns it, so nothing disables this one. This is the case the “a layout with it?” chip is supposed to notice.
2
The print dialog OWNED MODAL — the important one A real Windows dialog owned by this window. While it stands, this window is disabled, and Windows hides the dialog if this window is minimized. That pair is what nailed the layout down.
3
The file picker OWNED MODAL The same shape as the print dialog, from a different Windows subsystem. If one behaves and the other does not, the cause is not the ownership rule.
4
An image, in a window of its own TOP-LEVEL — new tab or window Opens the picture beside this page. Use this one to check the chip after a plain single click, rather than a double click.
Open the image
5
The image in the Photos app TOP-LEVEL — another process Save it, then double-click the saved file in Explorer through the stream. A new window of a different process is the cleanest case for the chip, and a double click is what the offer waits for.
Save the image
Nothing here talks to the server. It only makes windows, so the server can be watched while it decides what to do with them.
